# Quiet Ledger: release gates

Updated 2026-09-07. This is a checklist, not a claim of release readiness.

## Verified locally

- Real local browser preview at 390x844: overview, settings and subscription form render; measured page width does not exceed viewport and modal fits horizontally. Escape was fixed and verified in browser and a component test. Preview used demo data/emulator configuration; no production writes. This is not full mobile-device or live-auth QA.

- Local Git repository initialized with one local root commit; no remote or upload exists. Local environment, generated private rules, dependencies, build output, logs, backup directory and service-account filename patterns are excluded. The root commit is being amended before any remote is added so owner identity does not remain in reachable Git history. This is not a complete secret scan.

- Second component test confirms explicit restore confirmation, visible network error, retained backup for retry, successful retry into the current UID and success feedback. The dialog now states that settings are restored. Network failure is mocked; real connection interruption is not yet tested.
- Public mode now supports Google or email/password sign-in, password reset and mandatory email verification. Until verification succeeds and the ID token is refreshed, no user data stream starts. The Auth emulator suite also verifies account deletion and that the deleted account can no longer sign in. The live Firebase email provider is not enabled or tested yet.

- Sixteen Auth/Firestore emulator tests pass, including a complete 400-record private restore, repeated restore, simultaneous imports without duplicates, atomic rejection of invalid/oversized imports, account deletion and the public three-slot authorization boundary.
- Backup restore now restores validated settings in the same transaction as subscriptions. It creates missing settings, replaces only the three user preference fields on existing settings, preserves ownership/timestamps and remains atomic at the 400-record limit. Emulator, UI and production-build checks pass.

- UI regression test passes for direct Alice-to-Bob account switching, late Alice snapshots and logout. Session changes clear records/settings/errors; prior callbacks are invalidated; tracker state remounts per UID. This is a component test with mocked authentication/data streams, not a live Google sign-in test.

- Private-rule integration tests cover owner CRUD, unauthenticated/foreign denial, invalid claims, cross-account writes, schema validation, repeatable restore preserving edits and concurrent profile/settings initialization.

- 21 application unit tests, 20 UI component tests, 4 Gmail-backend security unit tests and 16 Auth/Firestore emulator integration tests pass; both TypeScript packages, private production build and public production build pass.
- Dependency audit on 2026-09-07 initially found eight development-tool vulnerabilities. Vite was upgraded from 7.1.4 to 8.2.2 and an advisory-fixed compatible esbuild was pinned. The production dependency audit now reports no known vulnerabilities; all unit/UI tests and the production build pass after the upgrade. The latest Firebase CLI was then added for reproducible emulator tests; its unshipped development-only dependency tree currently reports five moderate upstream advisories. CI audits production dependencies and runs the CLI only against the demo emulator. This is a time-bound registry audit, not proof that dependencies contain no unknown vulnerabilities.
- pnpm lifecycle execution is explicitly allowlisted only for `@firebase/util`, `esbuild`, `protobufjs` and the Firebase CLI's `re2`; installation and application build completed. The local `re2` native rebuild could not verify its downloaded prebuild and could not compile under the Codex runtime, but Firebase CLI 15.29.0 starts and all 16 emulator tests pass with the prepared portable Java 21; CI still needs its first clean-run confirmation.
- GitHub verification workflow is prepared but not uploaded or executed remotely. It uses read-only repository permissions, disables persisted checkout credentials, pins checkout/setup actions to the current official major-tag commits, installs locked dependencies, runs unit/UI/build/production-audit checks, executes Firestore tests and the public browser flow against the demo project. Local Firebase and browser suites pass with the project-local CLI.
- Money input is parsed into integer minor units from decimal digits; excess precision, exponent/hex notation, zero, negatives and out-of-range values are rejected rather than silently rounded. Boundary cases are tested.
- Eighth emulator integration test validates the public-rule candidate with two independent verified accounts: own CRUD succeeds, cross-account reads/updates/deletes and ownership forgery fail. Anonymous/unverified access fails.
- Public-rule coverage now includes profiles and private settings: each verified account can access its own documents, while foreign profile/email reads, foreign settings reads, user-directory listing, email mutation, settings-owner mutation and arbitrary private documents are denied.
- Public rules and UI now provide explicit deletion of all application data and the Firebase Authentication account. Deletion first creates an immutable per-UID tombstone; all later profile, settings and subscription creates/updates are denied while bounded cleanup runs. Cleanup is tested above 400 records and cannot touch another account. Authentication deletion is bound to the originally confirmed User object, so an in-flight browser account switch cannot delete the replacement account. A stale login is signed out and must authenticate again before retrying deletion.
- `firestore.public.rules` is referenced only by the separate public deployment configuration. Frontend public admission requires explicit `VITE_ACCESS_MODE=public`; default remains private. Private admission fails closed if owner UID is missing, and private rules are generated locally from an identity-free tracked template.
- Public deployment now has an explicit `firebase.public.json`, `.env.public`, `build:public` and `deploy:public`; the default build/deploy remains private. `deploy:public` always runs the full release gate first. The public build changes robots to `index, follow`, while the default build stays `noindex`. The release check requires all Firebase/App Check values plus a valid public support email, and refuses to deploy if paid features are enabled without their trusted backend.
- Privacy and terms drafts are reachable before sign-in and from settings. They document Firebase processing, no inbox access from ordinary sign-in, export/deletion and the manual nature of forecasts. Different currencies are displayed separately and are not combined using a stale conversion rate. The drafts still require owner review and a public contact address.
- Email registration requires an explicit terms/privacy checkbox; the Google continuation control has adjacent acceptance disclosure and direct links. The deletion dialog and privacy draft disclose the retained UID-only tombstone used to prevent stale-session data resurrection.
- Every created profile records the accepted terms version and server timestamp. Firestore rules require the current version, permit a one-time migration for a pre-launch legacy profile and then make the consent record immutable; emulator coverage verifies both enforcement paths.
- Versioned backup export excludes server/account metadata and round-trips through the parser. Legacy unversioned copies remain accepted. Unknown versions and oversized UTF-8 files are rejected.
- Recurring dates preserve the original monthly/yearly anchor; list and overview use projected dates.
- Calendar now renders every active monthly/yearly occurrence inside the next 12-month horizon instead of only one date per subscription. Month-end clamping, leap-year recovery, paused exclusion, stable keys and original-anchor preservation are tested. A UI test confirms 12 rendered monthly occurrences and that opening a projected row still edits the original stored anchor.
- Date-only display is stable across time zones. The screen refreshes the calendar day on focus, visibility changes and every 30 seconds.
- Backup parsing rejects malformed records and duplicate IDs; restore uses a transaction and skips existing IDs.
- Public accounts are limited to three deterministic subscription slots by Firestore rules as well as the UI; oversized restore is atomic. Token claims do not remove this boundary in the launch candidate. Legacy paid-era records remain readable/exportable/deletable but are excluded from totals and cannot be edited. Paid mode stays disabled until a trusted backend can verify provider webhooks, enforce a finite server-side quota and issue/revoke entitlements.
- Private and public builds use separate `dist` and `dist-public` directories. The public bundle check rejects private owner identity and verifies the explicit indexing policy.
- Every local/CI verification scans tracked and non-ignored source files for private owner identifiers, private keys, OAuth authorization codes, common cloud/payment tokens and non-empty secret-like environment variables. The check reports only file and credential class, never the matched value. Weekly Dependabot minor/patch updates are prepared for the future GitHub repository.
- Public signed-out mode now has a responsive product introduction and a local-only annual-cost calculator. The component test verifies recalculation without authentication or data streams. Desktop rendering was visually inspected, and a Chromium E2E test at 390x844 verifies no horizontal overflow.
- The public browser E2E suite registers and verifies two separate email accounts through the Auth emulator, saves settings, exports a versioned identity-free backup, restores it under another account, deletes that temporary account, signs back in and verifies data isolation and persistence. It also exposed and now covers the mobile logout control and route reset. This is strong local evidence, but not a substitute for live Firebase QA.
- Free-plan restore now resolves deterministic slot-ID collisions by comparing record content and assigning a different free slot. It preserves distinct same-value entries within one backup, remains repeatable on a second import and still rejects more than three records atomically. Emulator and browser regression coverage pass.

## Implemented, still needs integration verification

- Profile creation uses a transaction to avoid concurrent first-login overwrites.
- Settings initialization uses a transaction, preserves an existing document, and reports initialization failures without an unhandled rejection.
- Restore has emulator coverage for empty/repeated/concurrent/denied/maximum-size/invalid imports. Real-browser import UX and interrupted-network recovery still need verification.
- Date refresh and editing an original recurrence anchor need browser verification.

## Required before public launch

- Live multi-user Google sign-in and end-to-end checks after coordinated activation of the tested public rules and UI mode. Current production rules remain owner-only.
- Enable Firebase email/password authentication, configure sender/action-link templates and run live create/verify/reset/login checks.
- Live end-to-end account, CRUD, import, settings, mobile and recovery checks. Registration, verification, basic CRUD, settings, export/import, account deletion, mobile layout/logout and two-account isolation now have local browser coverage; recovery retains Auth emulator/component coverage.
- Re-run the repository security review after the final payment/mail/backend changes. A standard local Codex Security scan completed on 2026-09-07 with two medium and two low findings in the pre-launch code. Independent fix review confirmed that the local patch closes direct paid-claim/unbounded-ID writes and unbounded list queries, makes legacy IDs read-only and inactive in calculations, binds Authentication deletion to the confirmed account, and blocks concurrent repopulation with an immutable deletion tombstone. The archive UI intentionally loads at most 400 historical records; larger legacy migrations require a future paginated support flow.
- GitHub destination and visibility, source upload, verified Firebase deployment and post-deployment checks.
- Owner review of privacy/terms is still required. The public support/privacy email is now configured and the local release check passes.
- Gmail: the settings page shows a disabled, explicit future-integration control and states that the mailbox is not currently read. The implementation/security/verification contract is recorded in `INTEGRATIONS_PLAN.md` and `GMAIL_INTEGRATION_SPEC.md`. The production consent flow, deployed token storage, live disconnect/revocation, Google verification and any required security assessment are not configured or approved.
- Gmail backend foundation: a separate, non-deployed Functions package implements OAuth start/callback/disconnect boundaries with App Check on callable endpoints, hashed expiring one-use state, exact-scope validation, recent-authentication enforcement and Cloud KMS token encryption. Client Firestore access to its top-level state/token/rate-limit collections is denied and emulator-tested. Four pure security tests and TypeScript compilation pass. Live OAuth, KMS/IAM, revocation failure recovery, message discovery, account-deletion orchestration and Google review remain unverified or unimplemented; the public control stays disabled and `deploy:public` does not deploy Functions.
- Public UI no longer exposes the internal “ЛЁД” codename. A component test verifies its absence before and after sign-in; the underlying authorization, App Check and deletion controls are unchanged. The existing private site still shows the owner-only label until a later private deployment.
- Paid subscriptions: owner onboarding with the final provider, server-verified payments, idempotent webhooks, subscription lifecycle and sandbox tests. Not implemented. The owner confirmed Russia, adulthood and willingness to register as self-employed, and prefers payouts to a Mir card. YooKassa remains the documented candidate, subject to provider approval and the owner's direct onboarding. Do not collect card numbers, identity documents or provider secrets in chat.
- Own domain is deferred. Do not imply the default hosting address settles Google's production OAuth domain requirements.

No live deployment or GitHub upload was performed for the local changes listed above. Completion email remains cancelled. Do not enable Stripe or Resend implicitly.
