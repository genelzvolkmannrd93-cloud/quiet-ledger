# Quiet Ledger — сохранённое рабочее состояние

Дата фиксации: 4 сентября 2026 года.

## Рабочая версия

- Сайт: https://quiet-ledger-private-2026.web.app
- Firebase project ID: `quiet-ledger-private-2026`
- Тариф: Firebase Spark, без подключённого биллинга
- Вход: Google, только подтверждённый аккаунт владельца
- Хранилище: Cloud Firestore
- Stripe и Resend не используются

## Защита «ЛЁД»

- Доступ одновременно ограничен email и UID владельца.
- App Check принудительно включён для Authentication и Cloud Firestore.
- Firestore закрыт по умолчанию и проверяет схему каждой записи.
- Неавторизованный запрос к Firestore проверен: HTTP 403.
- Включены CSP, HSTS, запрет встраивания во фреймы и другие защитные заголовки.
- `.env.local` исключён из будущей публикации в GitHub через `.gitignore`.

## Проверено

- Google-вход и восстановление сессии после перезагрузки.
- Добавление, редактирование, пауза, возобновление и удаление подписки.
- Отображение роста цены.
- Обзор месячных и годовых расходов, категории и календарь.
- Настройки напоминаний и локальный экспорт резервной копии.
- Производственная сборка и автоматические тесты доменной логики.
- После проверки тестовые подписки удалены, порог напоминания возвращён к 3 дням.

## Продолжение 7 сентября 2026 года

- Подготовлена переносимая Java 21; локальные эмуляторы Auth и Firestore запускаются. Проходят 13 интеграционных тестов, 20 unit-тестов и 11 UI-тестов.
- Добавлены регистрация и вход по email/паролю, подтверждение email, повторная отправка подтверждения и восстановление пароля. Обычная авторизация не запрашивает доступ к содержимому Gmail.
- Добавлено подтверждённое удаление всей ветки данных пользователя с выходом; правила разрешают удалять только собственные подписки, настройки и профиль. Проверено удаление более 400 подписок несколькими пакетами.
- Личная и публичная сборки/конфигурации разделены. По умолчанию сохраняются закрытые правила и `noindex`; публичная сборка требует отдельной команды и отдельной конфигурации правил.
- Добавлены черновики политики конфиденциальности и условий. Стоп-кран публичного релиза требует контактный email и сейчас ожидаемо останавливается на `VITE_SUPPORT_EMAIL`.
- Production-аудит npm на эту дату не нашёл известных уязвимостей. Локальные изменения не опубликованы и на GitHub не отправлены.
- Итог текущего локального этапа: 20 unit-тестов, 15 UI-тестов и 16 Auth/Firestore integration-тестов проходят. Переносимая Java 21 найдена и подключена к повторному локальному запуску без изменения системного PATH; GitHub workflow явно устанавливает Temurin 21 перед этим тестом.
- Бесплатный публичный тариф ограничен тремя подписками правилами Firestore и интерфейсом. Платный тариф принимает только серверный token claim `plan=paid`; платёжный backend и выдача claim ещё не реализованы.
- Валюты больше не складываются по фиксированному устаревающему курсу: RUB, USD и EUR показываются отдельными итогами.
- Удаление аккаунта очищает данные и учётную запись Firebase Authentication; для чувствительной операции предусмотрен повторный свежий вход.
- Закрытая сборка использует `dist`, публичная — `dist-public`. Публичный пакет автоматически проверяется на отсутствие email/UID владельца.
- Настоящие email и UID владельца удалены из отслеживаемых файлов. Приватные правила генерируются локально из шаблона в исключённый каталог `.generated`. Единственный локальный коммит безопасно переписан; удалённого репозитория и публикации по-прежнему нет.
- В публичную страницу до входа добавлены описание продукта и локальный калькулятор годовых расходов. Введённые числа не отправляются в Firebase. Широкая версия проверена снимком; окончательная проверка на реальном телефоне остаётся обязательной перед запуском.
- Добавлен воспроизводимый браузерный E2E‑тест на ширине 390 px: калькулятор, регистрация и подтверждение двух временных email‑аккаунтов, создание подписок, выход, повторный вход и взаимная изоляция данных проходят на локальных Auth/Firestore‑эмуляторах. Тест нашёл отсутствие мобильного выхода; аватар в верхней панели превращён в доступную кнопку выхода. GitHub CI теперь запускает этот сценарий автоматически.
- Браузерный E2E расширен: он сохраняет настройки, скачивает резервную копию без метаданных аккаунта, импортирует её другому временному пользователю, удаляет этого пользователя и проверяет данные исходного аккаунта после повторного входа. Исправлена коллизия `free-1…3`: отличающаяся импортируемая запись теперь занимает свободный слот, а не пропускается молча; повторный импорт остаётся идемпотентным.
- В `pnpm verify` добавлен скан исходников и новых неигнорируемых файлов на приватные идентификаторы владельца, ключи, OAuth‑коды и распространённые форматы токенов. Проверка проходит и не выводит найденные значения. Для будущего GitHub подготовлены еженедельные Dependabot minor/patch‑обновления.

## Усиление безопасности 7 сентября 2026 года

- Завершён стандартный локальный аудит безопасности. Он нашёл два средних риска в незавершённой модели платного тарифа и два низких риска в удалении аккаунта; критических и высоких проблем не найдено.
- До появления доверенного платёжного backend публичный режим жёстко ограничен документами `free-1`…`free-3`; даже claim `plan=paid` не разрешает произвольные идентификаторы или массовый импорт. Старые записи с другими идентификаторами остаются доступными для просмотра, экспорта и удаления, но не редактируются и не входят в расчёты.
- Удаление данных начинается с неизменяемой отметки UID, которая блокирует повторное создание и изменение данных во время пакетной очистки. Удаление Firebase Authentication выполняется только для того объекта пользователя, для которого было подтверждено удаление; смена аккаунта в соседней вкладке не перенаправляет операцию на новый аккаунт.
- Команда публичной публикации теперь всегда запускает полный release-check; проверка отдельно запрещает включать платные возможности без серверной платёжной части.
- После изменений проходят 21 unit-тест, 19 UI-тестов, 16 Auth/Firestore integration-тестов и публичный браузерный E2E. Изменения по-прежнему только локальные: рабочий закрытый сайт не менялся, GitHub не подключён.
- Профиль пользователя теперь хранит версию принятых условий и серверное время согласия. Правила Firestore требуют актуальную версию, допускают однократное заполнение для старого профиля и запрещают дальнейшее изменение этих полей; оба сценария проверены эмулятором.
- В публичной конфигурации указан подтверждённый владельцем адрес поддержки; полный локальный `release:check` теперь проходит. Пароли, платёжные ключи и OAuth-токены в исходники не добавлялись.
