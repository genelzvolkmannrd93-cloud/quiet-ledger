# Тихий счёт — Google/Firebase версия

## Быстрое добавление и безопасное удаление

В окне новой подписки доступны восемь локальных шаблонов сервисов: они подставляют только название и категорию, не меняют введённую цену, валюту, период, дату и заметку. Значки не загружаются со сторонних сайтов. Поиск подписок учитывает название и заметки; сортировка сумм по-прежнему разделяет валюты.

После подтверждения удаления есть восемь секунд на «Отменить удаление». До истечения срока запись остаётся в базе и расчётах; отмена не выполняет никаких записей в базу. Выход из аккаунта или перезагрузка страницы до истечения срока отменяют отложенное действие. Открытие редактирования или переключение статуса этой подписки также отменяют его. После отправки удаления в базу отмена уже недоступна.

## Разработка и готовность к запуску

Локальный вход с реальной базой: открывайте `http://localhost:5173/`, не LAN-адрес. При обязательном App Check требуется зарегистрированный отладочный ключ в **игнорируемом** `.env.local`: `LOCAL_APP_CHECK_DEBUG_TOKEN`. Это приватная настройка разработки; не добавляйте значение в GitHub. Сервер запускается только на loopback; конфигурация запрещает сетевой запуск с таким ключом. Производственные сборки не получают его, а проверка сборки ищет утечку ключа в обеих версиях. Эмуляторы не требуют реального App Check. При проблемах со всплывающим окном используйте «Войти без всплывающего окна»; результат перенаправления обрабатывается при возврате. Реальный Google-вход проверяйте в обычном Chrome, если встроенный браузер не видит loopback-сервер.

Текущая опубликованная версия — личная, закрытая. Локальная подготовка публичной версии ещё не завершена; актуальные ограничения перечислены в `RELEASE_READINESS.md`. Описанные ниже проверки публикации относятся к ранее опубликованной личной версии, а не к новым локальным изменениям.

Для локальной разработки нужны Node.js 24 и pnpm. Будущие облачные функции закреплены на Node.js 22. Установка: `pnpm install --frozen-lockfile`. Основные проверки: `pnpm verify`; она включает отдельные тесты и TypeScript-сборку пакета `functions`.

Для проверок базы нужны Java 21 и Firebase CLI. Запуск из каталога проекта:

```sh
pnpm test:firestore
```

Эта команда использует зафиксированный в проекте Firebase CLI и отдельный демонстрационный проект. Не заменяйте его на рабочий проект для тестов. Интеграционный тест отказывается запускаться без локального эмулятора.

Публичный путь целиком проверяется командой `pnpm test:public-e2e`. Ей дополнительно нужен установленный Chrome/Chromium. Тест запускает локальную публичную сборку и Firebase‑эмуляторы, регистрирует и подтверждает два временных аккаунта, проверяет подписки, настройки, русский и английский интерфейс, удаление аккаунта и изоляцию на мобильной ширине. Рабочий Firebase при этом не используется.

Файл `.github/workflows/verify.yml` запускает общую команду `pnpm verify`, проверки правил и публичный браузерный сценарий в GitHub без ключей Firebase и без публикации. Поэтому локальная и серверная проверки не расходятся: в обеих проверяются исходники на секреты, интерфейс, серверный пакет, две сборки и зависимости. Сторонние Actions закреплены полными идентификаторами версий и получают только чтение содержимого репозитория. `check-source-secrets.mjs` останавливает проверку при появлении отслеживаемого приватного ключа, OAuth-кода, известного формата токена, непустой секретной переменной или локального идентификатора владельца. Dependabot подготовлен для еженедельных безопасных minor/patch-обновлений.

Стандартная сборка в `dist` остаётся закрытой. Перед закрытой публикацией `pnpm deploy` сначала выполняет полный `pnpm verify`, затем создаёт локальные правила из `firestore.private.rules.template`; полученный файл находится в `.generated` и не попадает в Git. `firestore.public.rules` — отдельный проверяемый кандидат для многопользовательского режима. Команда `pnpm build:public` создаёт публичный интерфейс только в `dist-public`, но сама не меняет разрешения базы. Публичная публикация использует только отдельную команду `pnpm deploy:public` и конфигурацию `firebase.public.json`; включать интерфейс и правила можно только совместно после завершения проверок запуска.

Перед публичной публикацией выполните `pnpm release:check`. Проверка намеренно требует Java, Chrome/Chromium, `VITE_SUPPORT_EMAIL`, полной Firebase/App Check конфигурации и собранной публичной страницы с явной политикой индексирования. В обычном состоянии сайт остаётся закрытым и не индексируется.

Перед передачей кода проверьте исключения `.gitignore`: локальные переменные окружения, резервные копии, ключи и журналы не должны попадать в GitHub. Настоящие серверные секреты никогда не помещаются в переменные `VITE_*`.

Трекер подписок без Stripe и почтовой рассылки. Текущая опубликованная версия закрыта; локальная публичная версия поддерживает Google и email/password с подтверждением адреса. Данные хранятся в Cloud Firestore, интерфейс доступен на русском и английском, а пользователь может полностью удалить свою ветку и аккаунт. Экспорт и восстановление резервных копий удалены из продукта. Границы будущих YooKassa, Gmail и почтовых уведомлений зафиксированы в `INTEGRATIONS_PLAN.md`, а защитный контракт Gmail — в `GMAIL_INTEGRATION_SPEC.md`. После проверки исполняемый OAuth-каркас Gmail намеренно удалён: пакет не экспортирует облачных функций и не может получить доступ к почте. Интеграция будет реализована отдельно после домена, биллинга и проверки Google.

До входа публичная версия объясняет назначение сервиса и содержит локальный калькулятор примерных годовых расходов. Значения калькулятора не сохраняются и не передаются в Firebase.

На первом публичном запуске каждый аккаунт может хранить до трёх подписок. Ограничение задаётся конечным набором документов `free-1`…`free-3` в правилах Firestore, поэтому его нельзя снять изменением браузерного кода или token claim. Ранее созданные записи с другими идентификаторами видны как архив: они не входят в расчёты, их нельзя менять, но можно просматривать или удалить. Слушатель архива и правила чтения ограничены 400 документами на запрос. Платный режим намеренно выключен до появления доверенного платёжного backend с конечной серверной квотой и постраничным чтением.

Удаление аккаунта сначала создаёт неизменяемую отметку удаления, после которой правила запрещают заново создавать или изменять профиль, настройки и подписки этого UID. Затем клиент очищает данные ограниченными пакетами и удаляет учётную запись Firebase Authentication. Если Firebase потребует свежий вход, пользователь может войти и безопасно повторить завершение операции.

Рабочий адрес: https://quiet-ledger-private-2026.web.app

Проект работает на бесплатном плане Firebase Spark. Stripe, Resend и платёжный аккаунт Google Cloud не подключены.

## Безопасность

- в закрытом режиме — вход только через подтверждённый Google-аккаунт владельца;
- Firestore закрыт по умолчанию, правила разрешают доступ только к ветке текущего владельца;
- строгая схема и ограничения для каждой записи;
- Firebase App Check с reCAPTCHA Enterprise;
- обязательный App Check для Authentication и Cloud Firestore;
- CSP и защитные HTTP-заголовки;
- отсутствие секретных серверных ключей в клиентском коде;
- тесты доменной логики и отдельная проверка правил перед публикацией.

Политика раскрытия уязвимостей и границы проверки описаны в `SECURITY.md`. Стандартный аудит безопасности выполнен локально; найденные проблемы платного лимита и смены аккаунта закрыты в текущей локальной версии, а защита удаления усилена неизменяемой отметкой.

## Подключение Firebase

1. Создать проект Firebase и веб-приложение.
2. Включить Google provider в Authentication.
3. Создать Firestore в production mode.
4. Скопировать `.env.example` в `.env.local` и заполнить публичную конфигурацию веб-приложения.
5. Для закрытого режима после первого входа записать UID и email владельца в локальный `.env.local`; они используются для создания локальных правил и не сохраняются в Git.
6. Создать ключ reCAPTCHA Enterprise для App Check и заполнить `VITE_RECAPTCHA_ENTERPRISE_SITE_KEY`.
7. Связать проект командой `firebase use --add`, затем опубликовать правила и Hosting.

## Состояние публикации

- Google-вход проверен на рабочем домене;
- доступ закреплён одновременно за email и UID владельца;
- создание, изменение, пауза, возобновление и удаление подписки проверены;
- расчёты и проверка вводимых данных покрыты автоматическими тестами;
- чтение Firestore без авторизации отклоняется;
- App Check для входа и базы переведён в режим Enforced;
- после проверки временные данные удалены, настройки возвращены к 3 дням.

Email и UID владельца находятся только в локальном `.env.local`. Перед закрытой публикацией скрипт создаёт приватные правила из безопасного шаблона; сгенерированный файл исключён из Git.
